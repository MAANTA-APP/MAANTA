## 1. The manifest made a trading claim, and the guard could not see the file

### What was true

`maanta-app/public/manifest.webmanifest`, line 4:

```json
"description": "Discover, claim and redeem live mall deals. Now live at BBS Mall, Eastleigh."
```

"Now live at" is the **first alternative in the guard's own `TRADING` regex**
(`prelaunch-consistency.test.ts`). The guard never fired because its *scope*, not
its pattern, was the gap: it walks `.tsx` under `src/app/(marketing)` and
`src/components/marketing` plus two named files. `public/` was outside coverage
by construction.

This is the worst-placed instance of the claim, not the least. The manifest
description is what the **Android install prompt** and the app listing render, at
the exact moment someone installs, on a surface `PrelaunchNotice` provably cannot
follow. Same argument D46 made for the OG image and D87 for the root meta
description. The company is neither incorporated nor ODPC-registered
(`src/lib/marketing/demo.ts`), so the claim is false in the way that matters.

**Third occurrence of D87's shape**, and the reason is structural: D87 closed by
routing 21 claim sites through `live-claims.ts`, gated on `DEMO_MODE`. **A static
JSON file cannot read a flag.**

### What shipped

**(a) The manifest is code.** `src/app/manifest.ts`, Next's `app/manifest` file
convention — verified against the Next 14.2 docs *and then against the build*,
which is the check that mattered:

| Verified from the build output | Result |
|---|---|
| Serves at the same URL | `.next/server/app/manifest.webmanifest` exists |
| Layout reference unchanged | built HTML: exactly **one** `rel="manifest" href="/manifest.webmanifest"` |
| Description is gated | served body reads `"Launching at BBS Mall, Eastleigh."` |

The description comes from a new `SITE_DESCRIPTION` in `live-claims.ts`, which
the root metadata now uses too. The same sentence had been a `DEMO_MODE` ternary
in `layout.tsx` **and** a frozen post-launch literal in the manifest — one claim,
two literals, which is precisely the shape D87 exists to prevent. The static file
is deleted; two manifests would be worse than one wrong one.

**(b) The guard enumerates `public/`.** Extensions `.webmanifest`, `.json`,
`.txt`, `.svg`, `.js`, `.md` — a directory walk, never a path list, for the D52
and D38 reason that a list only checks what someone remembered. It also reads the
generated manifest's own `name`/`short_name`/`description` through all three
patterns.

**One thing worth knowing about (b).** The old root-description check read
`layout.tsx` and split it on `DEMO_MODE` to isolate the pre-launch branch of a
ternary. That worked while the ternary lived there, and would have gone
**vacuously green** the moment it moved — the split would have found the import
line and matched nothing. This change moves it, so the check was rewritten to
assert the resolved constant. A guard that silently stops asserting when the code
it watches is refactored is worse than no guard, because it still reports green.

### Proved non-vacuous, in both placements

| Mutation | Result |
|---|---|
| Original string restored to `public/manifest.webmanifest` | ✗ fails: `manifest.webmanifest  →  "Now live at"` |
| Same string written into the generated manifest | ✗ fails: manifest case |
| Both removed | ✓ 6/6 green |

## 2. D93's repo-side half, finished — and the funnel still unproven

Two of the row's claims were **already stale** when re-read: the manifest
declared two icons, not "exactly one … `purpose: "any maskable"`", and
`layout.tsx` did set `apple: "/apple-icon"`. Of what genuinely remained, both
repo-side items shipped:

- **Raster PNGs at 192 and 512, both purposes.** Generated by
  `src/app/icons/[icon]/route.tsx` from `src/lib/brand/app-icons.ts`, verified in
  the build as real `192 x 192` and `512 x 512` PNG files. Generated rather than
  committed for the reason `apple-icon.tsx` already gives — *a committed binary is
  a second copy that nothing checks*. That is also a correction to
  `write-brand-icons.mjs`, whose docblock says manifest icons must be static
  "because … a generated Next route cannot give [a stable URL]": true of the
  metadata file conventions, which hash their URLs; not true of a route handler.
- **`appleWebApp` metadata.** Verified in the built HTML as three
  `apple-mobile-web-app-*` tags. The iOS home-screen title is now "Maanta"
  instead of the truncated document title.

**Which artwork, and why it matters.** These rasterise `mark.ts` — the *previous*
shield — not the newly supplied `public/brand/maanta-icon.png`. **D114** is
explicit that the supplied icon waits for a square opaque export, and the founder
instruction was to wire the lockups and wait. Rasterising the mark that already
ships as the manifest icon changes the format, not the brand. `brand-icons.test.ts`
now fails if the icon route ever references a `/brand/` URL, so that constraint
outlives this session.

**The funnel is still unproven, and that is now its own row (D139).** `public/sw.js`
still has no `fetch` handler (`grep -c` returns 0, re-measured), so whether
`beforeinstallprompt` ever fires in production is unknown, and `/download`'s
primary CTA may still be dead code on every visit. D93's remaining half is a
**device measurement**, not a repo task, and keeping the two in one row invites
the next reader to treat shipped icons as a working funnel.

at all — three different rooting styles across the file, 21 of 32 entries
unrooted — which is now **D140**.
