| 2026-07-21 | **Top-ups settle arrears FIRST** — code corrected to match the frozen rule (ENGINEERING_NOTES §3; boards M6 arrears / M7 top-up: "arrears settle first, remainder credits your balance, never pre-credit"). The prior `record_merchant_ledger_entry` credited the full top-up straight to `account_balance` and never touched `outstanding_arrears`, so a merchant who owed arrears kept **both** the full balance and the full arrears — the opposite of the frozen behaviour. Debit/refund path and idempotency unchanged. This corrects a code divergence — it does **not** change any frozen rule. | migration `20260721120000_topup_settles_arrears_first.sql` (`arrears_settlement` added to the `merchant_transactions` type CHECK; `CREATE OR REPLACE record_merchant_ledger_entry`); both webhooks (`/api/webhooks/{intasend,stripe}`) inherit it via `recordMerchantTransaction`; `src/lib/merchant-ledger.ts` type union. **DoD (§8.4/§8.2/§8.5) closed the same session:** money-path SQL tests `supabase/tests/{verify_redemption_money_path,topup_settles_arrears}_test.sql` (double-verify one-winner, owed@20, unknown+fraud task, settle-first, ledger reconciliation — validated locally against Postgres 16 with a Supabase shim, run in CI `db-tests`); `/demo` index of seeded logins (`src/app/demo/page.tsx`); a frozen-UI enforcement test `src/lib/__tests__/frozen-ui-rules.test.ts` (money-never-amber, closed vocabulary, failure-dark-not-red) plus fixing two money-in-amber violations (`plan/upgrade`, `pricing` → `text-white`). |
