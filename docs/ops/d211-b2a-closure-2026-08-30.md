## Blocking defect closed

The SQL contract admitted only `status = 'success'` parents into
`classified`. That was correct for earned totals but incomplete for validation:
a fee RPC can move a merchant wallet against a caller-supplied reference to a
pending or failed redemption. The movement then joined an existing parent, so
it was not `unparented`, while the success filter prevented every other CTE from
seeing it. The result could be available zero while money had moved.

`non_success_movements` now counts in-window and unplaceable fee-bearing rows
against genuine non-success parents as invalid. It scopes on every merchant the
chain can name: redemption, movement, deal owner and reversal audit. The audit
table's reverse-direction check no longer discards a malformed audit merely
because its redemption is non-success.

Shared semantic coverage:

- `fee-against-non-success-redemption-is-invalid`
- `audit-against-non-success-redemption-is-invalid`

Both are recorded as B2b TypeScript gaps because the current reader discards
non-success parents before aggregation.
